# VM Deployment Demo Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Kargo pipeline (dev → qa → sit → uat → prod) that promotes a Go service, its rendered config, and a Packer-built Ubuntu base image onto Proxmox VMs via Ansible run from a self-hosted GitHub Actions runner.

**Architecture:** Kargo (homelab agent shard) renders per-stage `config.yaml` + `deploy.yaml` into `rendered/vm-demo/<stage>` branches of `sedemo-platform`, then dispatches `converge.yml` in private `sedemo-vm-infra`, which runs Terraform (VM lifecycle) and Ansible (app deploy) on an ARC runner in the homelab cluster. Verification jobs on the homelab cluster discover VMs by Proxmox tag and check `/healthz`.

**Tech Stack:** Go 1.23, Helm 3, Packer + `hashicorp/proxmox` plugin, Terraform + `bpg/proxmox`, Ansible + `community.general.proxmox` inventory, ORAS, Kargo 1.11+ on Akuity Platform, ARC `gha-runner-scale-set`, Flux.

**Spec:** `docs/superpowers/specs/2026-10-12-vm-demo-design.md`

## Global Constraints

- No customer or person names in any file, commit message, branch, PR title or body, in any repo.
- Repos: app in `akuity/sedemo-monorepo` (`vm-app/`), Kargo in `akuity/sedemo-platform` (`apps/vm-demo/`), infra in `akuity/sedemo-vm-infra` (private), homelab in `adamancini/fleet-infra`.
- Self-hosted runner registers only to `akuity/sedemo-vm-infra`; label `homelab-vm-demo`.
- OS: Ubuntu 24.04 (`noble`) cloud image. Proxmox node `pve01`, storage `images`, bridge `vmbr0` (confirm in Task 0).
- DHCP only; no IP addresses in git. VMs tagged `vm-demo` and `stage-<stage>`.
- VMs and VMIDs: `vm-dev` 7101, `vm-qa` 7102, `vm-sit` 7103, `vm-uat` 7104, `vm-prod-1` 7105, `vm-prod-2` 7106. MACs `BC:24:11:D0:00:01` to `:06` in the same order. Seed template VMID 9100 `ubuntu-2404-seed`. Baked templates VMID `9101 + (run_number % 90)`, name `ubuntu-2404-base-<YYYYMMDDhhmm>`.
- Artifact: `ghcr.io/akuity/sedemo-monorepo-vm-app:<semver>` (plain `1.2.3` tags), one layer `nav-service_<ver>_linux_amd64.tar.gz` containing `nav-service` and `nav-service.service`.
- Service: listens `:8080`, config `/etc/nav-service/config.yaml`, binary `/usr/local/bin/nav-service`, user `nav`.
- Kargo stages carry `shard: homelab`. `kyverno-policy-check` is not used.
- Deviation from spec (repo convention): rendered output goes to branch `rendered/vm-demo/<stage>` (files `config.yaml`, `deploy.yaml` at root), not `env/<stage>/rendered/` on main. `converge.yml` input is `platform_ref` (a commit SHA on that branch).
- Deviation from spec (required for autoRollback): Ansible asserts `/version`, not `/healthz`, except when `healthz_gate=true` (prod only, to halt the rolling deploy). Health is Kargo verification's job; a failed promotion would leave the bad config on the VM and never trigger `autoRollback`.
- Deviation from spec (needed for prod's gate ordering): spec's single PromotionTask `vm-promote` is split into `vm-render` and `vm-converge` so prod can open the PR, create the CR, and wait on both before converging.
- Name scrub: before every commit, the orchestrator greps the diff for the names in the presenter's prep notes. The list is supplied at runtime and is never written to disk.
- Public repos: open a PR per task track; the presenter merges (or explicitly allows direct push).

## Review Focus

1. **Guest agent not yet reporting an IP** right after VM create/replace. Inventory and verification must wait/retry, and fail (not pass vacuously) when fewer VMs than expected are found. Tests: Task 7 Step 2, Task 11 Step 2.
2. **Re-promoting identical Freight** (autoRollback, retries) produces no git diff. The promotion must still succeed and still dispatch converge. Test: Task 10 Step 6.
3. **Two converge runs for one stage at once** (auto-promotion plus a manual click). Must serialize, not corrupt state. Test: Task 8 Step 3.
4. **A bad config during prod's rolling deploy** must stop after `vm-prod-1` and leave `vm-prod-2` on the old version. Test: Task 7 Step 4.
5. **Converge onto a freshly replaced VM** (base-image promotion) must install the app from scratch, tolerate a new SSH host key and possibly a new DHCP IP. Test: Task 15 Step 4.

## Addendum (2026-10-12, presenter decision): reuse `rollouts-app` instead of nav-service

Supersedes the nav-service parts of Tasks 1-3, 7, 9-11 and the spec's `vm-app/app` and artifact sections. Everything else stands.

- **App:** existing `ghcr.io/akuity/sedemo-monorepo-rollouts-app` (public; tags `^\d+-[a-z]+$`, e.g. `50-blue`). No new app, no new publish workflow, no new package. The demo promotes already-published tags only; publishing a new image is not part of the demo (five other demos watch this image).
- **Runs natively on the VM.** The image is `FROM scratch`: `/rollouts-demo` plus `*.html *.js *.png *.ico *.css` at `/`. Converge extracts it on the runner with `crane export <ref> - | tar -x` (install crane in `converge.yml`); Ansible copies files to `/opt/rollouts-demo/` (binary 0755, assets 0644, root-owned). The app serves assets from its working directory.
- **Service:** user `rollouts` (system, nologin) created by Ansible; static unit `ansible/files/rollouts-demo.service`: `WorkingDirectory=/opt/rollouts-demo`, `EnvironmentFile=/etc/rollouts-demo/rollouts-demo.env`, `ExecStart=/opt/rollouts-demo/rollouts-demo --listen-addr :8080 --termination-delay 1`, `User=rollouts`, `Restart=on-failure`, hardening as before. Packer base image drops the `nav` user and `/etc/nav-service`.
- **Config = env file.** `sedemo-monorepo/vm-app/config-chart` renders exactly `rollouts-demo.env`:
  `COLOR` (required, set by Kargo from tag suffix), `SEMVER` (required, the tag), `STAGE` (required, `ctx.stage`), `NAMESPACE` (required, per-stage from platform `env/<stage>/values.yaml`, value `vm-<stage>`), `ERROR_RATE` (default `0`, integer percent), `LATENCY` (default `0`). Kargo writes it to `rendered/vm-demo/<stage>/rollouts-demo.env` (replaces `config.yaml`); Ansible copies it verbatim to `/etc/rollouts-demo/rollouts-demo.env` (0640 root:rollouts). Helm's leading `---`/`# Source:` lines stay; systemd ignores them.
- **Warehouse** `app` (renamed from `nav-service`): image subscription `ghcr.io/akuity/sedemo-monorepo-rollouts-app`, `imageSelectionStrategy: NewestBuild`, `allowTagsRegexes: ['^\d+-[a-z]+$']`, `discoveryLimit: 10`; git subscription `sedemo-monorepo` `includePaths: [vm-app/config-chart]`. `deploy.yaml`: `app_version` = tag, `artifact` = `ghcr.io/akuity/sedemo-monorepo-rollouts-app:<tag>`.
- **Verification (`vm-health`):** per VM, `GET /env` must return `semver == appVersion` and `stage == <stage>`; `GET /color` 20 times, fail if more than 20% are non-200 (print the rate); qa smoke: `GET /` returns 200 and contains `<html`. `/healthz` is gone.
- **Ansible:** deploy asserts `/env` `.semver == app_version` (retries 20, delay 3). `healthz_gate` (prod) becomes: 10 consecutive `GET /color` all 200.
- **Failure scenarios:** render-time catch = remove `namespace` from `env/sit/values.yaml`; auto-rollback = set chart default `errorRate: 100`; prod rollback = promote the previous tag's Freight (bubbles visibly change color back).
